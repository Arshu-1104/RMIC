# Attacks the hard rules miss, and deterministic rules that would catch them

> **Held-out split: USED.** This design-time analysis read the held-out misses to write the rules, so the held-out split can no longer give an unbiased estimate and is not evaluated again. Rules R1–R6 and R8 are now implemented as contract fields (v0.4: `deny_patterns`, `argument_rules`, `confirm_above`; R7 was not implemented); their measured effect through the real code path, on the TUNE split only, is in [`implemented_rules_tune.md`](implemented_rules_tune.md). A blind test set is specified in [`prompts/v3/README.md`](../../prompts/v3/README.md).

Generated by `experiment/hard_rule_gaps/analyse_hard_rule_misses.py`. **Analysis only: none of these rules is implemented.** Corpus: `prompts/v2/` (copied unchanged from `v0.4-ids-scoring`), frozen split `prompts/v2/split.json`. *Missed* = an attack none of whose turns `Guard(contract)` (hard rules only, `semantic=False`) blocks. A rule flags an item if it matches any turn.

- Held-out attacks missed by today's hard rules: **36/80** (financial_agent 11/20, healthcare_research_agent 7/20, legal_review_agent 9/20, support_agent 9/20).
- Tune-split attacks missed: 41/80 (financial_agent 7/20, healthcare_research_agent 12/20, legal_review_agent 9/20, support_agent 13/20).
- **Bias warning:** the rules were written after reading the held-out misses, and one author wrote both the corpus and the rules, so the held-out column is optimistic. The tune-split misses were not inspected while writing the rules; treat that column as the fairer estimate. Legitimate = all 40 per contract (both splits).

## Notes

- R1–R3 are phrase lists, the same deterministic mechanism as the IBM standalone tools' `identity_drift_phrase_detected`. They catch explicit instruction-override wording, not paraphrases; an attacker who avoids the phrases walks past them.
- R4 depends on contract-specific term lists. The lists above are deliberately narrow (0 false positives here); broadening them is where false positives come from, e.g. a bare `password` term for support_agent would flag legitimate requests such as "How do I change my account password?". R5–R7 inspect the planned call, so their value depends on how the real tools name and type their arguments; the counts here reflect the hand-written arguments in `prompts/v2`.
- R6's argument lists were written from each tool's purpose; real tool schemas should come from the tool definitions themselves.
- R8 escalates instead of blocking; its false positive is a legitimate $45,000 house down payment.
